# 예외 처리·제한·검증 항목

> **범위**: 현재 구현의 실패 처리와 미보장 동작. 개선 요구사항을 이미 구현된 정책으로 해석하지 않습니다.

| 상황 | 현재 처리 | 영향·확인 사항 |
| --- | --- | --- |
| 기본 파일 없음/읽기 실패 | main이 null 반환 | 빈 상태 시작; 읽기 실패 자체는 토스트 없음 |
| 좌표 JSON 오류 또는 초기 IPC reject | 함께 로드한 Promise 체인 catch에서 로드 실패 토스트 | 원문 반영도 건너뛸 수 있음; 이후 좌표 자동 쓰기는 다시 활성화 |
| 원문이 공백뿐 | 파싱 배열 비움, 화면 유지 | 바로 실행은 빈 배열 안내; 기존 마커 객체는 남을 수 있음 |
| URL 누락·잘못된 문법 | 사전 차단 없음 | URL은 빈 문자열; 실행 접속 실패나 예상 밖 click 해석 가능 |
| 파일 dialog 취소 | null, 편집 상태 유지 | 기본 원문 저장까지 진행하지 않음 |
| 불러오기 읽기/기본 저장 실패 | importScenario에 catch 없음, App도 void 호출 | 전용 실패 토스트 보장 없음. 기본 저장 실패 시 화면 원문/활성 경로는 이미 변경될 수 있음 |
| 텍스트 저장 실패 | 토스트, savedMarkdown 갱신 안 함 | 외부 파일만 먼저 저장되었을 수 있음 |
| 마커 저장 실패 | 토스트 후 finally로 텍스트 복귀 | 화면 원문 또는 기본 파일은 이미 바뀌었을 수 있음 |
| 외부 파일 import 읽기 실패 | main 활성 경로는 이미 바뀌지만 renderer 경로는 이전 상태 | 이후 저장이 다른 파일 경로를 사용할 수 있으므로 다시 정상 불러오기 후 확인 |
| 구조가 잘못된 좌표 JSON | JSON 문법만 파싱하고 스키마 검증 없음 | 초기 catch 밖의 후속 렌더·effect 오류까지 토스트로 처리한다는 보장 없음 |
| 좌표 저장 실패 | 토스트 | 마커 편집 상태는 메모리에 남음 |
| WebView 추출 불가 | catch 후 수동 입력 대화상자 | 라벨 직접 입력·액션 확인 |
| inspect 도중 단계 수정·시나리오 전환 | 검사 요청 당시 scenario.steps로 응답을 반영; 요청 취소·최신성 검사 없음 | 늦은 응답이 최신 단계 편집을 덮어쓸 수 있음 |
| 빈 라벨 | 완료 비활성 및 훅의 trim 검사 | 값·URL·조건의 완전 검증은 아님 |
| inspect 실패 | 토스트, 기존 connected 상태 유지 | 클릭 대상 탐색의 예외 하나로 전체 inspect가 실패할 수 있음 |
| 이전 액션 뒤에만 존재하는 요소 | 기본 URL 검사로 연결 확인 불가 | 미연결이어도 실제 실행을 차단하지 않음 |
| 동일 단계/제목·URL 중복 | 좌표 매칭 첫 항목 또는 동일 키 사용 | 서로 다른 pin/occurrence를 정확히 복원하지 못할 수 있음 |
| 마커 저장·복제 직렬화 | 태그 유지; 표준 문장으로 재생성 | 주석·서식·fill/select 대기·manualFill value는 보존되지 않음 |
| 블록 교체 매칭 실패 | 현재 시나리오 단독 Markdown 반환 | 전체 원문이 대체될 수 있음 |
| 공백 블록이 낀 원문 | 파서는 trim으로 제거, 교체 함수는 filter(Boolean) 사용 | 파서 인덱스와 교체 블록 인덱스 불일치 가능 |
| 업로드 파일 이동/다른 PC | 경로 문자열만 유지 | 실행 머신에서 다시 선택 필요 |
| 상단 텍스트 탭/다른 화면 이동 | 저장 확인 없이 이동 | 복귀 확인 모달이 모든 이탈 경로를 보호하지 않음 |
| 마커의 직접 제어 안내 | 별도 창·미녹화로 안내하지만 실행은 headless·녹화 사용 | 실제 정책은 실행 문서 기준; UI 문구 불일치 |

## 정책 변경 전에 결정할 사항

현재 제한을 수정할 때에는 다음 기준을 먼저 정해야 합니다. 아래는 미구현 사항을 구현 완료로 간주하는 정책이 아닙니다.

| 결정할 사항 | 현재 동작 | 영향 받는 코드 |
| --- | --- | --- |
| 원문·마커의 단일 저장 기준과 이탈 시 처리 | 독립 상태·별도 저장, 일부 이탈만 확인 | useScenarioState, App |
| 저장 실패 시 되돌릴 범위 | 다중 파일 부분 성공 가능, rollback 없음 | fileStorage, useScenarioState |
| 안정적인 시나리오·단계 식별자 | 블록 순서 ID, 제목/URL·단계 속성 기반 좌표 매칭 | scenario.ts, useScenarioState |
| 문법 round-trip 보존 범위 | 일부 대기·값·주석은 직렬화 시 소실 | parseMarkdown, scenarioToMarkdown |

## 변경 시 검증 기준

1. 빈 원문·공백 입력에서 화면이 유지되고 바로 실행이 차단되는지 확인합니다.
2. 다중 블록 중 하나의 마커를 변경·재정렬한 뒤 저장/실행했을 때 대상 블록과 태그가 맞는지 확인합니다.
3. 복제의 기본값·다중 케이스·중복 이름·취소 초기화와 직렬화 제한을 확인합니다.
4. dialog 취소, 각 파일 쓰기 실패, 잘못된 좌표 JSON, 앱 재시작 후 원문·좌표·외부 경로 상태를 확인합니다.
5. 상단 모드 탭, 복귀 버튼, 하단 실행과 바로 실행의 서로 다른 경로를 확인합니다.

기존 테스트: [editor-empty-markdown.spec.ts](../../../tests/editor-empty-markdown.spec.ts), [scenario-duplication.spec.ts](../../../tests/scenario-duplication.spec.ts). 두 테스트는 electronAPI mock 기반 renderer 동작을 확인하며 실제 파일·WebView·Chromium 실행 검증을 대체하지 않습니다.
