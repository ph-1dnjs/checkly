# 사용자 흐름

1. 하단 `화면 테스트`로 이동합니다.
2. 주소를 입력하고 Enter를 누릅니다. `+`에서 브라우저 식별을 선택해 독립 세션을 추가할 수 있습니다.
3. 페이지 로드 후 필드를 자동 감지합니다. `다시 찾기`로 수동 감지도 가능합니다.
4. 정상 또는 오류 케이스를 선택합니다. 선택만으로 대상 폼은 바뀌지 않습니다.
5. 입력하지 않을 필드의 체크를 해제하고 값을 수정합니다. `케이스 설정`(…)에 제목·유형·전체 선택·전체 해제가 있습니다.
6. `N칸 입력하기`를 누릅니다. 체크 해제한 필드의 기존 값은 그대로 둡니다.
7. `케이스에 저장`으로 값과 체크 상태를 저장합니다. 지우개 버튼은 체크된 필드만 비웁니다.
8. 페이지에 직접 입력한 값은 `지금 화면 값으로 새 케이스`로 별도 저장합니다.

## 네트워크와 Swagger

1. 상단 `네트워크`를 엽니다. 전체·오류·스펙 경고 카드로 필터링합니다. HTTP·페이지 오류와 스키마 경고는 별도로 집계합니다.
2. 요청 행을 눌러 상세로 이동합니다. `요청 목록`으로 돌아갈 수 있습니다.
3. 기본 응답 표에서 값·타입을 확인합니다. 중첩 항목을 펼치거나 원본 JSON을 열 수 있습니다. `요청` 탭에서 메서드·주소·세션과 전송값을 봅니다.
4. 설정/API 테스트에 등록된 Swagger 문서를 자동 연결합니다. 명세의 타입·필수 여부 등은 `스펙 필드 상세`에서 확인합니다. 실제 쿼리 파라미터는 요청 탭에 표시합니다.
5. 하단 `이 응답 바꿔 보기`로 오버라이드를 만들거나 `스펙 복사`를 누릅니다. 목록 오른쪽 (…)에 다운로드·전체 삭제가 있습니다.

요청 상세는 검사 패널 전체를 사용합니다. 이전 버전의 목록/상세 높이 조절 대신 목록으로 돌아가는 흐름을 사용합니다.

## 응답 오버라이드

1. 네트워크 상세에서 실제 응답을 복제하거나 빈 화면에서 `직접 만들기`를 누릅니다.
2. 메서드·경로와 상태 코드 프리셋을 고르고 `항목으로` 또는 `JSON`에서 응답을 편집합니다.
3. `저장 및 적용`으로 저장합니다. 웹은 정확히 일치하는 요청을 다시 조회하고, 모바일은 앱에서 다음 일치 요청을 실행하면 적용됩니다.
4. `바꾼 응답 목록`에서 스위치로 적용 여부를 바꿉니다. 편집 화면 (…)의 `규칙 상태·고급 설정`에 사용자 상태 코드, 초기화, 삭제가 있습니다.

## 보기·화면 캡처

주소창 오른쪽 `보기`에서 브라우저 식별, 화면 크기, 배율, 개발자 도구·화면 집중을 엽니다. 모바일 375×667 / 390×844 / 412×915, 태블릿 768×1024를 선택하고 가로·세로를 전환할 수 있습니다. 배율을 바꿔도 반응형 기준 CSS 크기는 유지되며, 크기·방향은 재진입 시 복원됩니다. 퍼센트 버튼을 누르면 100%로 돌아갑니다.

Safari UA는 식별 정보만 변경하며 실제 엔진은 Chromium입니다. Safari 식별에서 모바일과 다른 크기 사이를 전환하면 페이지를 새로고침하므로 저장하지 않은 입력이 사라질 수 있습니다. 로그인 세션은 유지됩니다. 다른 브라우저 식별에서는 크기 변경만으로 새로고침하지 않습니다.

1. 헤더의 `캡처` 또는 `⌘/Ctrl + Shift + S`로 현재 작업 화면을 캡처합니다. 웹뷰에 포커스가 있어도 단축키가 동작합니다.
2. `영역 선택`으로 필요한 부분을 드래그하면 잘린 영역으로 이동하고 펜 도구가 활성화됩니다.
3. 펜·네모·체크·텍스트·지우개, 색상·굵기로 주석합니다. `전체 화면`은 원본으로 돌아갑니다.
4. 실행 취소·클립보드 복사를 사용하거나 취소합니다.
