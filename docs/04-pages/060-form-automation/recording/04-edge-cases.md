# 수집 제한과 복구

- 모든 폼 입력과 contenteditable, `[data-private]`, `.sentry-mask` 텍스트를 마스킹한다. `[data-checkly-block]`, `.sentry-block`은 기록에서 가린다. 일반 화면 텍스트는 재현을 위해 남는다.
- 로그는 URL의 사용자 정보·쿼리·해시를 제거한다. 요청·응답 본문, 쿠키·인증 헤더, 오류 메시지·스택은 팀 로그에 보내지 않는다. rrweb의 DOM 인라인 이벤트·data/토큰/비밀번호 속성도 제외한다.
- 재생 가능한 화면을 구성하려면 전 5초보다 앞선 직전 전체 스냅샷과 그 이후 DOM 변경이 파일에 포함될 수 있다. 플레이어의 표시 구간은 전후 5초로 제한한다. 시작 직후 오류이거나 브라우저를 일찍 닫으면 확보한 구간만 재생한다.
- 웹 시나리오는 오류 후 남은 5초를 수집한 뒤 브라우저를 닫는다. 사용자가 취소하거나 브라우저/앱을 먼저 닫으면 확보한 구간만 남긴다. 캡처 실패는 QA 결과를 바꾸지 않는다.
- Canvas·동영상 픽셀·다른 출처 iframe 내부는 지원하지 않는다. 외부 이미지·CSS·폰트는 원본 주소에 접근 가능해야 한다. rrweb 기록은 MP4/WebM 동영상이 아니다.
- 로그 전송과 오류 파일 업로드는 독립적이다. 오류 기록의 `trigger_log_id`는 파일과 로그를 연결하지만, 로그 전송 한도/강제 종료로 로그가 없을 수 있어 FK는 두지 않는다.
- Storage 성공 후 DB 저장이 실패하면 파일이 먼저 남을 수 있다. 동일 경로 덮어쓰기 재시도로 복구한다. 서버 보존 기간·자동 정리는 아직 없다.
- 팀 기록 조회 실패 시 로컬 사본을 표시하지만 업로드된 파일의 재생/삭제는 서버 연결이 필요하다. 다른 팀원이 삭제한 파일의 로컬 캐시는 다음 정상 조회에서 숨긴다.
- 로컬 오류 기록은 최대 50MB, 메모리 버퍼는 8MB다. 브라우저 종료 전달은 최대 3초 기다린다. 저장 실패·중단 복구는 [저장 계약](03-api.md)을 따른다.
