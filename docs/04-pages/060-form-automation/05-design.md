# 화면 테스트 v2 디자인·검증

사용자가 제공한 `Checkly 상용화 디자인 시스템 – Checkly 폼 자동 완성 v2.html`의 화면을 기준으로 적용했습니다. 시안의 예시 URL·계정·요청·기기·기록은 실제 앱 데이터로 대체하며, 시안 확인용 SCREEN 전환기는 앱에 포함하지 않습니다.

## 화면 대응

| 시안 상태 | 구현 |
| --- | --- |
| 처음 사용·폼 입력 | 52px 헤더, 상단 모드 탭, 44px 세션 행, 48px 주소 행, 440px 검사 패널, 안내 카드·3단계 폼·번호 표시·하단 입력 버튼 |
| 네트워크·요청 상세 | 전체/오류/스펙 경고 카드, 한 줄 요청 목록, 목록 복귀, 요청/응답 값 표와 원본 JSON, 상세 하단 버튼 |
| 오버라이드 빈 화면·편집 | 시작 안내, 응답 복제·직접 생성, 목록 스위치, method/path·상태 코드·항목/JSON 편집, 하단 저장 |
| 브라우저 기록·재생 | 전체 화면 헤더, 340px 목록, PC/서버 탭, 중앙 재생, 320px 타임라인, 하단 앱 내비게이션 |
| 모바일 연결 전·연결됨 | 기기/앱 도구 행, 폰 프레임, RN 연결 안내, 공통 네트워크/응답 패널, 텍스트 전송 |
| PC·모바일 캡처 | 어두운 배경, 16px 여백의 밝은 도구 막대, 영역/주석 도구, 네 색상, 굵기·취소·복사 |

추가 기능은 시안 구조 안의 메뉴에 유지합니다. 보기 메뉴에는 UA·viewport·회전·확대·개발자 도구·화면 집중, 케이스 메뉴에는 제목·유형·전체 선택, 규칙 메뉴에는 초기화·삭제·임의 상태 코드가 있습니다. Swagger 스키마의 자세한 표도 요청 상세에서 열 수 있습니다. 공용 Button/Input 크기 규칙을 따릅니다.

## 검증

```bash
npm run build
npx tsc --noEmit
npm test -- --reporter=line
npx tsx tests/screen-test.desktop.ts
npx tsx tests/form-viewport.desktop.ts
```

- UI 회귀 62개: 기존 시나리오·설정·인증 화면과 새 디자인 흐름 포함.
- 레이아웃: 1280×720, 1440×1000, 1920×1080에서 헤더/세션/주소 행 높이, 검사 패널 너비, 하단 버튼 접근 및 가로 넘침 검사.
- 실제 Electron: 별도 임시 프로필·로컬 HTTP fixture에서 감지, 번호 표시/정리, 명시적 입력, 제외 필드 유지, 저장/재시작, 현재 값 복제, 초기화, 네트워크 상세, 실제 fetch 응답 변경·스위치·원복, 오류 기록·재생, 세션 추가/이름/분할, 캡처 진입 검사.
- viewport: 실제 guest의 CSS 크기·반응형 CSS, 배율과 회전, 프리셋, 입력·세션 보존, 설정 복원 검사.
- 기록 UI: rrweb 재생·탐색·배속·API 상세를 실행하고, MP4·선택 전송·서버 삭제의 기존 IPC 계약은 테스트 대역으로 검사.
- 모바일 UI: 연결·앱 열기/재시작·텍스트·중앙 터치 좌표·네트워크·응답 변경·캡처·연결 해제의 기존 IPC 계약을 검사. 실제 iOS 시뮬레이터가 없는 환경이므로 실제 기기 연결·RN 앱 통신은 이 검증에 포함되지 않습니다.

`CHECKLY_SCREEN_TEST_OUTPUT=/절대/출력/경로`를 UI 또는 desktop 검사에 주면 화면 캡처를 저장합니다. 데스크톱 검사는 Retina 캡처의 배율 차이를 피하려고 `--force-device-scale-factor=1`을 사용합니다. 사용자 프로필과 팀 DB를 사용하지 않습니다.
