# [엣지 케이스] API 테스트

| 상황 | 현재 동작·후속 행동 |
| --- | --- |
| 명세 다운로드·파싱 실패 | 마지막 정상 명세 유지, 오류와 동기화 상태 확인 |
| 문서 401/403 | Basic 계정 확인 |
| 명세 주소 변경 | 인증 방식·아이디는 유지, 저장 계정은 정확히 같은 URL에서만 사용 |
| 동기화 후 경로가 바뀐 API | 명세 영역 경고·시나리오 목록 주황 점. 수정 화면의 `API 바꾸기`로 새 API 연결(값 유지, 새 API에 없는 요청 값은 목록으로 표시) |
| 동기화 후 제목이 바뀐 API | 이전 제목을 이름으로 쓰는 단계만 `새 제목으로 바꾸기` 대상. 직접 붙인 이름은 그대로. 제목 변경 기록은 이 기능 이후의 동기화부터 쌓임 |
| 같은 메서드·경로가 명세에 둘 이상 | API를 특정할 수 없어 사라진 API와 같은 경고 |
| OS 보안 저장 불가 / Linux basic_text | 계정 기억 비활성화, 평문 비밀번호 저장 없음 |
| 웹 서버·앱 재시작 | 프로젝트·명세·시나리오 복원, 전역변수·API 인증 연결 초기화 |
| API 토큰 삭제·잘못된 타입·기본 URL 변경 | 호출 전 차단, 재등록·재연결 |
| 개별 Authorization과 공통 인증 중복 | 하나를 해제해야 실행 가능 |
| 동일 ID 시나리오 저장 충돌 | 최신 updatedAt을 요구, 목록에서 다시 열기 |
| 초안 | 저장 가능해도 실행 검증은 통과해야 함 |
| 단계 이동·삭제 후 미정의 vars | 미리보기 issues, 실행 차단 |
| 요청·응답 값 출처가 사용 단계보다 뒤에 있음 | 자동 검증을 추가하지 않고 값 순서 오류만 표시, 순서를 바꾼 뒤 실행 |
| 요청·응답 출처 단계가 실패·건너뜀 | 출처 스냅샷을 만들지 않으므로 참조 단계는 blocked, `onFailure` 정책 적용 |
| 추출 경로 누락·검증 실패 | 해당 단계 실패, 그 단계 변수 변경 반영 안 함. 검증은 모두 확인해 각각의 ✓/✗와 실패 시 실제 값(80자, 민감 필드는 가림)을 결과에 표시 |
| 복제 이름 중복 | `사본`, 겹치면 `사본 2`·`사본 3`, 사본의 사본도 원래 이름 기준 |
| 비 JSON 요청 본문(multipart 등) | 실행 미지원. AI가 쓸 API 목록에서 흐리게 표시하고 선택 불가 |
| 동일 프로젝트 실행 중 (환경 무관) | 추가 실행·전역변수·인증 설정 변경 차단. 전역변수가 환경 간 공유되어 토큰 덮어쓰기를 막기 위함 |
| 세션 쿠키 | 응답 Set-Cookie를 프로젝트별 저장소에 보관해 이후 단계·시나리오·스위트·API 문서 호출이 함께 사용. 브라우저 규칙(Domain·기본 Path·Secure·Max-Age/Expires)을 따르며 요청 호스트와 무관한 Domain은 거부. 단계의 `cookies`에 직접 적은 값이 우선. 전역변수 팝오버에서 이름·도메인만 확인하고 비울 수 있음. 앱 종료·프로젝트 삭제 시 초기화 |
| 환경을 바꿔 가며 실행 | 전역변수가 프로젝트 공유이므로 다른 환경에서 저장한 토큰이 남아 있을 수 있음. 환경 전환 후 로그인 시나리오를 다시 실행 |
| 실행 중 API 페이지 이탈 | 취소 요청, 이미 서버에서 수행된 변경은 되돌리지 않음 |
| 실행 중 인증번호·추가 입력 | `step.input`에 설정하고 해당 단계에서 값이 없으면 모달을 표시. 제출 후 같은 요청부터 재개 |
| 실행 입력 취소·창 종료·5분 만료 | 대기 Promise 해제, 필수 입력은 blocked 처리, 이후 단계는 실패 정책에 따라 skipped/계속 |
| 실행 입력 타입 오류·늦은/중복 제출 | 제출을 거절하고 현재 요청을 유지하거나, 이미 끝난 요청이면 오류 반환 |
| 응답이 매우 빠름 | 로딩 표시가 짧거나 보이지 않을 수 있음, 인위적 지연 없음 |
| 첫 Swagger 펼침 | 지연 렌더링 비용 발생 가능, 이미 연 항목보다 느릴 수 있음 |
| Mermaid 파싱 실패 | 오류 표시 후 재시도 가능 |
| URL hash 공유 | 프로젝트·환경 선택은 복원하지 않음, 같은 명세가 필요 |
| 개별 원문 응답 | 민감값 포함 가능, 자동 저장하지 않음 |
| 시나리오 YAML에 직접 비밀값 입력 | 원문 저장되므로 inputs/globals 사용 |
| 결과 값 숨기기 | 백엔드는 원문 반환. **민감값 숨기기** 토글(기본 켬)이 민감 키의 값과 알려진 민감값만 CSS로 가림. 이름이 평범한 키에 담긴 개인정보(이메일·전화번호 등)는 탐지하지 않음. 요청 본문 JSON 입력칸은 부분 가림이 불가능해 가리지 않음. 개발자 도구에는 원문이 남고, 토글이 켜진 동안 JSON 복사 버튼은 숨김 |
| AI 작성 | 결과에서 시나리오 YAML을 찾지 못하면 오류. 한 번에 30개까지. 코드 블록 밖 글·빈 문서·일반 문장은 무시. YAML 오류·없는 API·id 중복(기존·결과 안)·결과 안의 이름 중복은 해당 초안의 문제로 표시하고 초안으로만 저장. 기존 시나리오와 이름이 같으면 경고만 표시. 스위트는 이름(또는 직접 쓴 id)으로 연결하며, 결과에 없는 이름이면 스위트 문제로 표시. 가이드가 1MB를 넘으면 태그로 좁히도록 안내. 결과 파일이 없으면 AI가 저장했는지 확인하라고 안내 |
| AI 전달 데이터 | 명세 설명과 업무 목표는 그대로 포함. 전역변수 값·서버 URL·예제값은 제외 |
| 묶음의 참조 시나리오 삭제·초안 전환 | 해당 시나리오는 설정 필요로 기록하고 실패 정책에 따라 중단/계속 |
| 스위트 실행 중 사용자 입력 | 기존 단계 입력 요청을 사용, 취소 시 대기 입력 해제 |
| HTML 리포트 | 실행 시점 요약만 생성. 검증별 ✓/✗와 검증 내용은 포함하지만 실제 응답 값·요청·응답 원문·변수 값은 포함하지 않으며 결과는 앱 재시작 시 사라짐 |

프로젝트 삭제는 연결된 로컬 API 데이터를 제거합니다. 서버·환경 삭제는 해당 범위 데이터와 시나리오 연결에 영향을 주므로 삭제 UI의 설명을 확인합니다. 명세 삭제는 시나리오 자체를 삭제하지 않지만 해당 API를 사용하는 실행은 다시 명세를 가져올 때까지 검증에 실패할 수 있습니다.

## 지원 제한

OpenAPI 3.0/3.1, JSON/YAML, 내부 ref, JSON 본문을 대상으로 합니다. 명세 최대 5MB, 시나리오 YAML 최대 1MB입니다. 외부 ref·Swagger 2.0·multipart·복합 파라미터 직렬화·완전한 요청 본문 스키마 검증은 지원 범위에 포함되지 않습니다.

묶음의 별도 YAML 파서, 실행 이력 영구 저장, 전역변수 영구 저장·만료, 단계별 실시간 진행률, OAuth 자동 인증, 쿠키 세션 자동 수집·갱신, 조건 분기·cleanup, 동일 환경 병렬 실행, Java/k6 변환은 미구현입니다. 묶음 정의는 프로젝트별로 저장되며 결과는 메모리에만 유지됩니다. HTML 리포트는 사용자가 명시적으로 내보낼 때만 저장됩니다. API 단계의 실행 중 입력 모달은 구현되어 있지만, 자동 SMS 발송·외부 입력 공급자 연동은 제공하지 않습니다. 단순 쿠키 파라미터를 시나리오의 `request.cookies`로 입력해 `Cookie` 헤더로 보내는 기능과 시나리오 단계별 시각 편집은 구현되어 있습니다.

## 수동 확인 범위

로컬 샘플로 명세 Basic 인증, 전역변수 Bearer 연결, 상품 조회, 여러 단계의 vars 재사용, 시나리오 저장·재실행, 서버 재시작 후 데이터 복원과 세션 초기화를 확인할 수 있습니다. 실제 업무 서버 호출은 해당 환경과 입력을 확인한 뒤 수행합니다.

UI의 시나리오 로딩바는 결과 영역에 표시되는 대기 애니메이션입니다. 실제 완료 퍼센트를 의미하지 않습니다. 실행 중 입력 대기 시에는 로딩바의 상태 문구를 입력 대기로 바꾸고 모달을 표시합니다. DESIGN.md v14의 teal 강조색·헤어라인·조밀한 컨트롤·3px 진행바를 적용합니다. React에서는 목업 전용 sc-for/sc-if 대신 기존 JSX를 사용합니다. 기존 화면 CSS와 Swagger 스타일 연동은 유지하며, 목업의 인라인 스타일 전용 규칙으로 전체를 변환하지는 않았습니다. Swagger의 API 메서드 구분색은 문서 탐색의 일관성을 위해 유지합니다.
