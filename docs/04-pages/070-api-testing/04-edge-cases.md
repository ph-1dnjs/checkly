# [엣지 케이스] API 테스트

| 상황 | 현재 동작·후속 행동 |
| --- | --- |
| 명세 다운로드·파싱 실패 | 마지막 정상 명세 유지, 오류와 동기화 상태 확인 |
| 문서 401/403 | Basic 계정 확인 |
| 명세 주소 변경 | 인증 방식·아이디는 유지, 저장 계정은 정확히 같은 URL에서만 사용 |
| 동기화 후 경로가 바뀐 API | 명세 영역 경고·시나리오 목록 주황 점. 수정 화면의 `API 바꾸기`로 새 API 연결(값 유지, 이 API 명세에 없는 요청값은 목록으로 표시) |
| 동기화 후 제목이 바뀐 API | 이전 제목을 이름으로 쓰는 단계만 `새 제목으로 바꾸기` 대상. 직접 붙인 이름은 그대로. 시나리오별 `이대로 두기`는 그 제안만 숨기고, 제목이 다시 바뀌면 다시 안내. 사라진 API가 함께 있어도 이름 변경은 적용. 제목 변경 기록은 이 기능 이후의 동기화부터 쌓임 |
| 같은 메서드·경로가 명세에 둘 이상 | API를 특정할 수 없어 사라진 API와 같은 경고 |
| OS 보안 저장 불가 / Linux basic_text | 계정 기억 비활성화, 평문 비밀번호 저장 없음 |
| 웹 서버·앱 재시작 | 프로젝트·명세·시나리오·스위트 정의 복원, 전역변수·세션 쿠키·API 인증 연결 초기화 |
| API 토큰 삭제·잘못된 타입·기본 URL 변경 | 호출 전 차단, 재등록·재연결 |
| 개별 Authorization과 공통 인증 중복 | 하나를 해제해야 실행 가능 |
| 동일 ID 시나리오 저장 충돌 | 최신 updatedAt을 요구, 목록에서 다시 열기 |
| 초안 | YAML 파싱과 저장 충돌 검사는 통과해야 함. API 연결 등 구성 문제는 초안으로 저장할 수 있지만 실행하려면 문제를 해결하고 일반 저장 필요 |
| 실행 전 전역변수·서버 URL 누락 | 미리보기 executionIssues에 표시. 일반 저장은 가능하며 실행은 차단 |
| 앞 단계가 생성할 인증 토큰 | 이전 단계의 extract에 정의되어 있으면 사전 검사에서 기존 토큰 값을 요구하지 않음. 실제 추출값은 인증 요청 직전에 검사하며 유효하지 않으면 해당 단계는 blocked이고 요청을 보내지 않음. 같은 단계·뒤 단계의 추출만으로는 사전 검사를 통과하지 못함 |
| 단계 이동·삭제 후 값 연결 | 같은 단계·뒤 단계 참조는 파싱 또는 미리보기에서 거부. 삭제된 출처의 연결은 YAML 직렬화 시 빈 값으로 바뀌므로 연결과 필수 요청값을 다시 확인 |
| 요청·응답 값 출처가 사용 단계보다 뒤에 있음 | 자동 검증을 추가하지 않고 값 순서 오류만 표시, 순서를 바꾼 뒤 실행 |
| 요청·응답 출처 단계가 실패·건너뜀 | 요청 해석 후·응답 검증 전에 만들어진 스냅샷은 실패해도 남음. `onFailure: continue`이면 후속 단계에서 실패 응답도 참조 가능. 건너뛰었거나 스냅샷 생성 전에 실패해 값이 없으면 참조 단계는 blocked |
| 추출 경로 누락·검증 실패 | 해당 단계 실패, 그 단계의 extract 결과는 반영 안 함. 앞 단계 값 연결·실행 입력으로 이미 설정된 vars는 유지. 검증별 ✓/✗와 실패 시 실제 값(80자)을 반환하며 화면에는 원문 그대로 표시 |
| 복제 이름 중복 | `사본`, 겹치면 `사본 2`·`사본 3`, 사본의 사본도 원래 이름 기준 |
| 비 JSON 요청 본문(multipart 등) | 실행 미지원. AI가 쓸 API 목록에서 흐리게 표시하고 선택 불가 |
| 동일 프로젝트 실행 중 (환경 무관) | 추가 실행·전역변수·인증 설정 변경 차단. 전역변수가 환경 간 공유되어 토큰 덮어쓰기를 막기 위함 |
| 세션 쿠키 | 응답 Set-Cookie를 프로젝트별 저장소에 보관해 이후 단계·시나리오·스위트·API 문서 호출이 함께 사용. 브라우저 규칙(Domain·기본 Path·Secure·Max-Age/Expires)을 따르며 요청 호스트와 무관한 Domain은 거부. 단계의 `cookies`에 직접 적은 값이 우선. 전역변수 팝오버에서 이름·도메인만 확인하고 비울 수 있음. 앱 종료·프로젝트 삭제 시 초기화 |
| API 문서 호출의 필수 쿠키 | 명시적 cookies 또는 최종 요청 URL에 전송 가능한 프로젝트 세션 쿠키로 충족. 다른 호스트·경로·Secure 조건에 맞지 않거나 만료된 쿠키는 인정하지 않음. 명시한 빈 값은 저장 쿠키보다 우선하므로 필수 입력 오류 |
| 환경을 바꿔 가며 실행 | 전역변수와 쿠키 저장소는 프로젝트 단위로 공유. 다른 환경의 토큰이 남거나 URL 범위가 맞는 쿠키가 전송될 수 있으므로 환경 전환 후 필요한 값을 정리하고 로그인 시나리오를 다시 실행 |
| 시나리오 작성 중 환경 전환 | 새 시나리오와 기존 시나리오의 미저장 수정·편집 단계를 유지. 명세 로딩·없음·조회 실패 시에도 편집기를 닫지 않으며, API 문서에는 현재 환경의 명세만 표시. 요청 입력칸은 마지막으로 확인한 필드를 유지해 미완성 JSON과 검증 오류를 보존. 저장·실행 검사는 현재 환경을 기준으로 수행 |
| 실행 중 API 페이지 이탈 | 취소 요청, 이미 서버에서 수행된 변경은 되돌리지 않음 |
| 실행 중 인증번호·추가 입력 | 단계의 `inputs` 목록에 정의하고 `{{inputs.name}}`으로 사용. 같은 이름의 사용 가능한 값이 없으면 모달을 표시하고 제출 후 같은 요청부터 재개 |
| 실행 입력 중 취소 | 대기와 진행 요청을 중단. 현재·후속 단계는 cancelled이며 `onFailure: continue`여도 호출을 계속하지 않음 |
| 입력 대기 중 창 종료·5분 만료 | 값 없이 대기를 해제. 필수 입력은 blocked 처리하며 이후 단계는 실패 정책에 따라 skipped/계속. 페이지 이탈로 별도 취소 신호가 전달된 경우에는 cancelled |
| 실행 입력 타입 오류·늦은/중복 제출 | 제출을 거절하고 현재 요청을 유지하거나, 이미 끝난 요청이면 오류 반환 |
| 응답이 매우 빠름 | 로딩 표시가 짧거나 보이지 않을 수 있음, 인위적 지연 없음 |
| 첫 Swagger 펼침 | 지연 렌더링 비용 발생 가능, 이미 연 항목보다 느릴 수 있음 |
| Mermaid 파싱 실패 | 오류 표시 후 재시도 가능 |
| URL hash 공유 | 프로젝트·환경 선택은 복원하지 않음, 같은 명세가 필요 |
| 개별 원문 응답 | 민감값 포함 가능, 자동 저장하지 않음 |
| 시나리오 YAML에 직접 비밀값 입력 | 원문 저장되므로 inputs/globals 사용 |
| 결과 값 표시 | Swagger처럼 원문 표시. 화면 공유·녹화 시 토큰이 보이므로 주의. 새 토큰·문서 비밀번호 입력칸은 항상 가리고, 전역변수 패널의 값은 기본 숨김(`값 보기`로 전환, 이 기기에 기억) |
| AI 대화 | 이 환경에 명세가 하나도 없으면 AI 탭 비활성. 첫 화면은 방식 선택이며 CLI·백엔드 폴더가 모두 있어야 대화 선택 가능(가이드 복사는 항상 가능). 기억한 대화 방식의 조건이 깨지면 방식 선택으로 돌아감. 지정한 폴더가 사라졌으면 시작 거부. 설정에서 고른 CLI가 없어졌으면 설치된 다른 CLI 사용. 로그인 필요·모델 오류는 해결 방법을 함께 표시. 시작·전송·초기화·프로젝트 삭제는 저장 대기 전부터 프로젝트 단위로 잠그며 답하는 중에는 보내기·초기화 불가(중단 가능). 초기화 준비·저장 실패 시 이전 대화를 유지. 저장하지 않은 최신 검사 결과가 있을 때만 초기화 확인. 환경 불일치 시 기록만 읽고 현재 환경으로 초기화. 검사·저장은 대화 환경을 사용. 첫 답이 실패하면 다음 메시지가 새 세션에서 가이드와 함께 다시 시작. 자동 수정은 최대 2회, 이후 결과를 그대로 저장하면 초안. 검사 중 중단하면 "중단했습니다"와 검사 결과를 표시. 답에서 ```yaml 블록과 `steps:`·`suite:`가 있는 언어 표시 없는 블록만 결과로 검사(계획의 폴더 구조·코드 예시는 무시). AI가 답하는 중에는 프로젝트 삭제 불가. 앱 종료 시 진행 중인 CLI를 중단 |
| AI 작성 | 결과에서 시나리오 YAML을 찾지 못하면 오류. 한 번에 30개까지. 코드 블록 밖 글·빈 문서·일반 문장은 무시. YAML 오류·없는 API·id 중복(기존·결과 안)·결과 안의 이름 중복은 해당 항목의 문제로 표시. 문제 항목은 초안 저장을 시도하지만 YAML 파싱 오류·저장 ID 충돌은 먼저 고쳐야 함. 기존 시나리오와 이름이 같으면 경고만 표시. 스위트는 이름(또는 직접 쓴 id)으로 연결하며, 결과에 없는 이름이면 스위트 문제로 표시. 가이드가 1MB를 넘으면 태그로 좁히도록 안내. 결과 파일이 없으면 AI가 저장했는지 확인하라고 안내 |
| AI 전달 데이터 | 가이드에는 서버 이름과 파일 경로를 포함. 전역변수 이름·타입·생산/사용 시나리오, 기존 그룹, 저장된 시나리오 YAML·스위트는 project-state.json, API 설명·요청/응답 스키마는 api-catalog.json으로 제공. 앱 대화는 별도 chat 폴더의 명세·상태를 매 요청 전에 갱신하며 가이드 복사와 파일을 공유하지 않음. 시나리오 YAML에 직접 적은 값은 그대로 전달. 서버 기본 URL·전역변수 값·명세 예제/default/enum 값은 내보내기 필드에서 제외하며, 명세 등에 반복된 현재 전역변수 문자열은 6자 이상일 때 가림. 설명에 직접 적힌 다른 비밀값을 모두 탐지하지는 않음. 업무 목표는 Checkly 입력이 아니며 가이드를 받은 외부 AI가 사용자에게 먼저 질문 |
| 묶음의 참조 시나리오 삭제·초안 전환 | 해당 시나리오는 설정 필요로 기록하고 실패 정책에 따라 중단/계속 |
| 스위트 실행 중 사용자 입력 | 기존 단계 입력 요청을 사용, 취소 시 대기 입력 해제 |
| HTML 리포트 | 실행 시점 요약만 생성. 검증별 ✓/✗와 검증 내용은 포함하지만 실제 응답 값·요청·응답 원문·변수 값은 포함하지 않으며 결과는 앱 재시작 시 사라짐 |

프로젝트 삭제는 연결된 로컬 API 데이터를 제거합니다. 서버·환경 삭제는 해당 범위 데이터와 시나리오 연결에 영향을 주므로 삭제 UI의 설명을 확인합니다. 명세 삭제는 시나리오 자체를 삭제하지 않지만 해당 API를 사용하는 실행은 다시 명세를 가져올 때까지 검증에 실패할 수 있습니다.

## 지원 제한

OpenAPI 3.0/3.1, JSON/YAML, 내부 ref, JSON 본문을 대상으로 합니다. 명세 최대 5MB, 시나리오 YAML 최대 1MB입니다. 외부 ref·Swagger 2.0·multipart·완전한 요청 본문 스키마 검증은 지원하지 않습니다. 경로·헤더·쿠키의 배열/객체 파라미터도 실행 미지원입니다.

쿼리 직렬화기는 배열의 form·spaceDelimited·pipeDelimited, 객체의 form·deepObject를 지원합니다. deepObject의 explode=false는 지원하지 않습니다. 스칼라는 form·simple을 허용합니다. 시나리오 실행과 API 문서 직접 호출 모두 operationId 유무와 관계없이 명세의 쿼리 직렬화 설정과 본문 스키마를 사용합니다. 선택적 본문은 생략할 수 있으며, 본문이 있으면 지원 범위 내 타입·필수 필드 오류를 HTTP 전송 전에 검사합니다.

묶음은 AI 결과의 `suite: { name, group?, scenarios: [...] }` 문서에서 가져오거나 화면에서 구성합니다. 별도 범용 스위트 실행 YAML 문법은 제공하지 않습니다. 실행 이력 영구 저장, 전역변수 영구 저장·만료, 단계별 실시간 진행률, OAuth 자동 인증, 조건 분기·cleanup, 같은 프로젝트의 병렬 실행, Java/k6 변환은 미구현입니다. 묶음 정의는 프로젝트별로 저장되며 결과는 메모리에만 유지됩니다. HTML 리포트는 사용자가 명시적으로 내보낼 때만 저장됩니다. 실행 중 입력 모달은 구현되어 있지만 자동 SMS 발송·외부 입력 공급자 연동은 제공하지 않습니다. 세션 쿠키 자동 수집·갱신, 단계 바로 아래 `cookies`를 통한 명시적 Cookie 전송, 시나리오 단계별 편집은 지원합니다.

## 수동 확인 범위

로컬 샘플로 명세 Basic 인증, 전역변수 Bearer 연결, 상품 조회, `steps.N`·`inputs` 참조를 통한 단계 간 값 재사용, 시나리오 저장·재실행, 서버 재시작 후 데이터 복원과 세션 초기화를 확인할 수 있습니다. 실제 업무 서버 호출은 해당 환경과 입력을 확인한 뒤 수행합니다.

UI의 시나리오 로딩바는 결과 영역에 표시되는 대기 애니메이션입니다. 실제 완료 퍼센트를 의미하지 않습니다. 실행 중 입력 대기 시에는 상태 문구를 입력 대기로 바꾸고 모달을 표시합니다. API 화면은 공통 `--ck-*` 디자인 토큰을 사용하며 기본 강조색은 `--ck-color-blue-action`입니다. Swagger의 API 메서드 구분색은 문서 탐색의 일관성을 위해 유지합니다.
