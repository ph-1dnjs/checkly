# 기능·실행 정책

## 진입과 모드

- 하단 독의 `smart_toy`(AI TC 실행) 메뉴. 큰 버튼은 단계에 따라 준비 → 실행 → 취소 → 결과 → 다시 실행으로 바뀝니다.
- 팀 모드(로그인): 프로젝트의 `web` 엔드포인트 × 환경을 씁니다. 시작 URL은 선택한 엔드포인트의 환경 주소, 허용 도메인은 같은 환경의 모든 웹 엔드포인트 host입니다. 선택은 시나리오 화면과 같은 개인 설정(localStorage)이며 공통 테이블은 바꾸지 않습니다.
- 로컬 모드(Supabase 설정 없음): 시작 URL과 추가 허용 도메인을 직접 입력합니다.
- 팀 DB에는 아무것도 저장하지 않습니다. 정책안 7절에 따라 팀 공유 저장은 확정 전까지 구현하지 않았고, 결과 화면에 그 사실을 표시합니다.

## 가져오기

- 사용자가 고른 `.xlsx`만 main에서 읽습니다. 원본은 바꾸지 않고, 경로는 renderer·모델에 넘기지 않습니다(파일명만).
- 확정한 상한: 파일 20MB, 시트 30개, 시트당 5,000행, 100열, 칸당 10,000자. 넘으면 가져오지 않고 이유를 토스트로 보여 줍니다.
- 머리글: 처음 15행 안에서 TC ID와 기대 결과(또는 테스트 단계)가 함께 있는 행. 없으면 참고 시트로 보고 선택할 수 없습니다.
- 기본 매핑: `TC ID`·`시나리오 ID`·`구분`·`사전 조건`·`테스트 단계`·`기대 결과`·`테스트 데이터`(공백·기호 무시, 별칭 포함). 매핑하지 않은 열은 "참고 열"로만 표시하며 실행 지시로 쓰지 않습니다.
- 숨긴 시트·행: 기본 제외, 가져오기 옵션으로 포함.
- 병합 셀: 병합 범위의 나머지 칸은 첫 칸 값을 이어받습니다. 단 TC ID·테스트 단계·기대 결과는 이어받지 않아 같은 TC가 여러 행으로 늘어나지 않습니다.
- 수식: 실행하지 않고 캐시된 결과만 씁니다. 결과가 없으면 빈 칸으로 보고 "값이 없는 수식 칸" 경고를 붙입니다.
- 번호·글머리 목록은 항목별로 나누고(번호 없는 줄은 앞 항목에 이어 붙임), 기대 결과는 `E1`, `E2`…로 번호를 매깁니다. "분리 수정"에서 한 줄 하나로 고칠 수 있으며 원문(`expectedRaw`)은 남습니다.
- 행 오류(실행 불가): 빈 ID, 중복 ID(파일 전체에서 처음 나온 행 다음부터), 테스트 단계 없음, 기대 결과 없음.
- 선행 후보: 사전 조건에서 `…-TC숫자` 형태 ID를 찾습니다. 파일에 없는 참조는 경고만 하고 자동 충족하지 않습니다. 선행 TC를 선택 해제하면 그것을 참조하는 선택도 함께 해제하고 6초 동안 되돌리기를 제공합니다.

## 준비

- 가져오기 화면에서 설치된 Claude CLI 또는 Codex CLI를 선택합니다. Claude가 설치되어 있으면 기본 선택이며, 선택한 CLI로 데이터를 준비하고 테스트를 실행합니다. 준비 후 도구를 바꿔도 이미 생성한 데이터는 유지됩니다.

- 선택한 TC마다 상태: 준비됨 / 입력 필요 / Blocked(선행으로 연결했는데 선행이 빠짐) / 제외.
- 준비 화면은 TC ID를 하이픈으로 나눈 접두어별 전체 선택을 제공합니다. 첫 두 단계는 항상 표시하고, 세 번째 단계부터는 현재 검색·필터 결과에서 해당 접두어의 TC가 2개 이상일 때만 표시합니다. 그룹 선택은 현재 보이는 TC에 적용됩니다.
- 선행 확인: 선행 TC가 모두 이번 실행에 있으면 자동으로 "선행으로 연결"됩니다. 그 밖에는 "선행으로 확인"(선행이 이번 실행에 있을 때, 선행이 Pass가 아니면 Blocked) 또는 "이미 준비됨"(사용자 확인을 근거로 실행). 확인 전에는 실행할 수 없으며, "남은 선행 모두 이미 준비됨으로 확인"으로 한 번에 처리할 수 있습니다. 연결한 선행은 먼저 실행되도록 정렬하고, 순환이면 실행하지 않습니다.
- 테스트 데이터 자동 세팅: 준비 화면에 들어오면 아직 세팅하지 않은 선택 TC를 하나씩 AI CLI에 보냅니다. 입력은 TC(사전 조건·단계·기대 결과·테스트 데이터 열)와 시나리오 시트에서 같은 시나리오 ID가 적힌 행, 오늘 날짜입니다. AI는 TC마다 입력값 목록과 업로드 파일 명세를 돌려줍니다.
  - 가져오기에서 AI 데이터 자동 준비를 끄면 모델 호출 없이 준비 화면에서 값을 직접 추가할 수 있다. `저장된 절차의 데이터 항목 불러오기`로 필요한 이름을 가져오며 기존 입력값은 유지한다. 필수 항목이 없거나 중복되면 실행 전에 항목 이름을 안내한다.
  - 날짜는 오늘 이후 실제 날짜, 중복되면 안 되는 값은 `QA자동_` 접두어를 씁니다. 정확한 글자 수가 필요한 값은 `{{len:N}}`으로 받아 앱이 정확히 N자로 만듭니다(모델이 글자 수를 자주 틀림).
  - 이미 시스템에 있어야 하는 데이터(상품·회원 등)는 지어내지 않고 "화면에서 조건에 맞는 항목을 고른다: <조건>"으로 받아 실행 중 화면에서 고릅니다.
  - 업로드 파일은 명세(png·jpg·pdf·txt·csv·xlsx, 가로×세로, 최대 KB)대로 OS 임시 폴더(`checkly-ai-tc-*`)에 만들어 업로드 토큰으로 자동 등록합니다. 이미지는 headless Chromium 캔버스로 정확한 크기로 그리고, JPEG는 용량 한도에 맞춰 품질을 낮춥니다. 앱이 정상 종료되면 임시 폴더를 지웁니다.
  - 선택한 TC를 하나씩 준비하고 완료 즉시 결과를 표시합니다. 현재 TC와 대기·실패 상태, 준비 및 실행 토큰 사용량은 AI 대화 패널에서 확인할 수 있습니다. 실행 중 제어 인계 요청과 답장은 현재 화면 세션에서 순서대로 쌓이며 새 실행을 시작하면 초기화됩니다.
  - 세팅한 값·파일은 TC별로 고치거나 지우고, 값·파일을 추가하거나 직접 고른 파일로 교체할 수 있습니다. "테스트 데이터 다시 세팅"은 선택한 TC를 처음부터 다시 만듭니다.
  - 세팅 중에는 실행할 수 없고, 세팅이 실패해도 실행은 막지 않습니다(부족한 값은 실행 중 AI가 사용자에게 넘김). 단계 문구로 데이터를 추정해 입력을 요구하던 방식은 없앴습니다.
- 실행 설정: 환경·시작 URL·허용 도메인, AI 제공자(설치된 Claude Code·Codex CLI 중 선택)와 전송 범위, 캡처·영상, 실행 한도.

## 실행

- 단일 Chromium(headless) 컨텍스트에서 TC를 순서대로 처리하고 TC 사이에 로그인·데이터 상태가 이어집니다. 브라우저 뷰포트는 실행 화면의 표시 영역 크기에 맞춰 변경됩니다. 사용자 대기 중 같은 페이지를 클릭·입력·스크롤하고 뒤로·앞으로·새로고침할 수 있습니다. 개발자 도구와 팝업 직접 제어는 지원하지 않습니다.
- AI 탐색은 관찰(URL·제목·접근성 트리, 이미지 전송을 켜면 화면 이미지) → CLI 호출 → 응답 검증 → Playwright 수행 → 재관찰이다. 같은 화면의 독립 입력은 모델이 준비된 값을 최대 3개까지 묶어 제안할 수 있다. 각 입력 사이에도 재관찰하며 이동·대상 오류·대화상자가 생기면 나머지 묶음을 버린다. 비밀번호 입력은 거부한다. 이미지의 AI 전송은 기본 꺼짐이며 로컬 근거 캡처 설정과 독립적이다.
- 허용 동작: `click`·`fill`·`select`·`press`·`scroll`·`wait`·`goto`(허용 도메인만)·`upload`(사용자가 고르거나 자동 생성한 파일만)·`judge`·`handoff`·`done`. 그 밖의 형식·필드는 거부하고 최대 2번 다시 묻습니다.
- 대상이 여럿이면 `nth` 없이는 고르지 않습니다(정확한 이름이 하나면 그것을 사용). 대상을 못 찾는 실패가 3번 이어지면 사용자에게 넘깁니다.
- 데이터 변경 클릭은 별도 확인 없이 실행하며 동작 이력에 기록합니다. 영상 기록은 기본으로 켜지고 결과 화면에서 다운로드할 수 있습니다. 원본 녹화는 다음 실행 시작 또는 앱 정상 종료 시 삭제됩니다.
- 한도(확정 전 기본값): TC당 동작 40회·10분, 실행 전체 모델 호출 300회. TC 한도를 넘으면 남은 항목은 `확인 필요`, 호출 예산을 넘으면 실행을 멈춥니다.
- 선택적으로 실행 전체·TC별 토큰 한도를 정할 수 있다. 80% 이상 사용하면 경고하고 완료된 호출을 합산해 다음 호출 전에 확인한다. TC별 한도는 해당 TC만 중단한다. 진행 중인 호출은 한도를 초과할 수 있고 준비 단계는 한도에서 제외된다. 필수 사용량을 확인하지 못하면 추가 호출을 중단한다.

## 재실행

- 성공한 실행은 동작과 검증 후보를 로컬에 저장한다. 결과 화면에서 기대 결과와 화면 문구가 정확히 일치하는 검증 조건을 승인할 수 있다. 입력값은 저장하지 않고 준비 데이터의 이름으로 참조한다.
- 준비 화면의 저장된 절차 실행은 TC 원문·환경·데이터 이름이 일치하는 절차를 현재 데이터로 실행한다. 결과 화면에서는 현재 실행을 바로 재실행할 수 있다. 등록·저장도 다시 수행하므로 시작 전 중복 가능성을 안내한다.
- 빠른 실행은 모든 기대 결과에 승인된 문구 조건이 필요하고 현재 화면을 다시 확인한다. 미승인 조건은 AI 보조 실행에서 현재 화면으로 판정할 수 있으며 TC당 모델 호출은 최대 3회다. 수동 단계는 두 방식 모두 차단한다.
- AI 보조 실행 중 동작이 실패하면 수정 후보를 보여 준다. 사용자가 같은 종류 동작의 대상만 임시 적용할 수 있고, 재검증에 성공할 때까지 기존 저장 절차는 변경하지 않는다.
- 이미지 전송을 끈 경우에도 근거 캡처·미리보기는 별도 설정에 따라 생성한다. 사용량은 입력·출력·캐시 및 미확인 호출을 보여 주며 구독 잔여량이나 실제 청구액은 아니다. 결과에서는 실행 호출을 탐색·동작, 판정, 형식 오류·실패, 수정 제안으로 구분하고 준비 사용량은 별도로 표시한다.

## 판정

- 기대 결과마다 판정·관찰·근거(k/v, URL 자동 추가)·캡처·시각·판정 주체(ai/automation/system/user)를 남깁니다.
- `done`으로 근거 없이 끝낸 항목은 `확인 필요`, 실행 불가 사유는 `Blocked`, 취소·오류로 도달하지 못한 항목은 `미실행`.
- TC 집계: Fail > Blocked > 확인 필요 > 미실행 > Pass, 모두 N/A면 N/A.
- 결과 화면에서 사용자가 판정을 바꾸면 원래 판정과 이유를 함께 남깁니다. N/A는 사용자만 지정할 수 있습니다.
