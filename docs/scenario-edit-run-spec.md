# Checkly: 시나리오 기반 QA 자동화 ‘체키’

## 시나리오 편집·실행 기획서

| 항목 | 내용 |
| --- | --- |
| 문서 상태 | 코드 기반 초안 · 정책 검토용 |
| 작성 기준 | 2026-09-28, Checkly 0.1.10 현재 작업 트리 |
| 대상 독자 | 기획자, 디자이너, QA 담당자, 개발자 |
| 범위 | 브라우저 QA 시나리오 작성·추출·복제·저장·선택·실행·수동 개입·결과 확인·재실행 |
| 범위 제외 | 독립 메뉴인 폼 자동화 및 API 테스트의 상세 기획 |
| 검증 범위 | 화면·상태 관리·실행 엔진 소스 대조. 실제 앱의 모든 흐름을 실행 검증한 문서는 아님 |

> 이 문서의 ‘현재 동작’은 구현에서 확인한 사실이다. ‘기획 의도’는 기능을 설명하기 위한 해석이며, ‘결정 필요’는 아직 확정하지 않은 정책이다. 커밋되지 않은 작업 내용도 작성 기준에 포함한다. 노션의 ‘시나리오 편집/실행’ 페이지 본문으로 사용할 수 있다.

### 1. 기능 개요

체키의 시나리오 편집·실행은 웹사이트에서 수행할 행동과 기대 결과를 단계별로 작성하고, 같은 흐름을 반복 실행하여 결과를 확인하는 기능이다. 사용자는 Markdown으로 시나리오를 작성하거나, 내장 웹 화면에서 대상을 선택해 실행 단계를 구성한다. 자동화가 어려운 인증·직접 조작·결과 판단은 수동 단계로 연결한다.

**기획 의도**는 반복적인 브라우저 QA를 재사용 가능한 시나리오로 관리하고, 실행 중 어느 단계에서 문제가 발생했는지 화면·로그·영상으로 확인하도록 돕는 것이다. 주요 사용자는 반복 검증을 수행하는 QA 담당자와 기능 변경 후 동작을 확인하는 기획자·개발자로 가정한다. 이 사용자 정의는 코드에서 확정할 수 없는 기획 해석이다.

| 사용자 요구 | 제공 기능 |
| --- | --- |
| 동일한 업무 흐름을 반복 확인하고 싶다 | 시나리오 저장 및 재실행 |
| 실행할 화면 요소를 쉽게 지정하고 싶다 | 화면에서 마커를 추가하고 액션 정의 |
| 같은 흐름에서 입력값과 기대 결과만 바꾸고 싶다 | 케이스별 시나리오 복제 |
| 여러 테스트를 한 번에 실행하고 싶다 | 여러 파일의 시나리오 선택 및 순차 실행 |
| 자동화 중 인증이나 사람의 판단이 필요하다 | 수동 입력·브라우저 직접 제어·수동 결과 확인 |
| 실패 지점과 당시 화면을 확인하고 싶다 | 단계별 결과, 캡처, 로그, 실행 영상 |

### 2. 화면 구성과 기본 흐름

**작성 또는 불러오기 → 미리보기 확인 → 필요 시 화면에서 단계 편집 → 저장 → 실행 → 수동 단계 응답 → 결과 확인 → 수정 또는 재실행**

저장된 파일을 사용할 때는 **폴더 선택 → 파일·시나리오 확인 → 실행 대상 선택 → 순차 실행**으로 진입한다. 저장은 재사용을 위한 행동이며, 실행의 필수 선행 조건은 아니다.

| 화면 | 주요 구성 | 사용자 행동 |
| --- | --- | --- |
| 시나리오 편집: 텍스트 | Markdown 입력, 시나리오별 미리보기, 시나리오·단계 수 | 작성, 불러오기, 저장, 복제, 화면에서 추출, 바로 실행 |
| 시나리오 편집: 화면에서 추출 | URL·웹 화면, 화면 폭 선택, 단계 목록, 마커, 액션 정의 창 | 시나리오 선택, 대상 추출, 단계 추가·수정·삭제·정렬 |
| 시나리오 선택 | 파일 목록, 시나리오 목록, 선택한 실행 대상 및 합계 | 폴더 변경·새로고침, 개별·파일 내 전체 선택, 단일·선택 실행 |
| 시나리오 실행 | 현재 단계·진행률, 시나리오별 단계 목록, 캡처·실시간 화면, 로그 | 실행 중단, 수동 개입, 화면 크기 조정, 세션 유지, 재실행 |
| 실행 기록 상세 | 실행 묶음의 결과 및 시나리오 정보 | 결과 확인, 해당 기록의 시나리오 재실행 |

### 3. 시나리오 작성 및 편집

#### 3.1 텍스트 작성

| ID | 항목 | 현재 동작 |
| --- | --- | --- |
| ED-01 | 초기 진입 | 저장된 기본 원문을 불러온다. 원문이 없으면 빈 상태로 시작하며 예제를 자동 삽입하지 않는다. |
| ED-02 | 실시간 미리보기 | 원문 변경 시 시나리오와 단계로 해석하여 제목·URL·액션 등을 표시한다. 시나리오별로 펼치거나 접을 수 있다. |
| ED-03 | 다중 시나리오 | 하나의 Markdown에 여러 시나리오를 작성할 수 있다. 텍스트 수정 시 현재 편집 대상은 첫 번째 시나리오로 설정된다. |
| ED-04 | 미저장 표시 | 원문이 마지막 저장 원문과 다르면 `UNSAVED`를 표시한다. 아직 원문에 반영하지 않은 마커 변경은 모두 감지하지 못한다. |
| ED-05 | 불러오기 | `.md`, `.markdown` 파일을 선택한다. 불러온 내용이 편집 원문을 대체하며 앱의 기본 원문에도 저장된다. |
| ED-06 | 바로 실행 | 현재 원문의 전체 시나리오를 실행한다. 마커 모드에서는 현재 마커 변경을 먼저 원문에 반영한다. 파일 저장을 수행하는 버튼은 아니다. |

표준 작성 예시는 다음과 같다. 주소·입력값·기대 결과는 테스트 대상에 맞게 변경한다.

```markdown
# 시나리오: 로그인 후 주문 조회
url: https://example.com
tag: regression

Given `/login` 페이지로 이동한다
And `이메일`에 `qa@example.com` 입력
And `비밀번호` 수동 입력 [테스트 계정의 비밀번호를 입력해 주세요]
When `로그인` 클릭 [대기 10초]
And 화면에 `공지`가 있는 경우 `닫기` 클릭 [대기 3초]
Then `주문 목록` 텍스트가 보인다 [대기 10초]
```

제목은 `# 시나리오: 제목`, 기본 주소는 소문자 `url:`, 선택적 태그는 소문자 `tag:`로 작성한다. 단계는 `Given`, `When`, `Then`, `And`, `But`, `If`로 시작하며, 접두사의 역할과 무관하게 작성된 순서대로 실행한다. 조건 분기는 `If` 자체가 아니라 ‘화면에 …가 있는 경우’ 문구로 지정한다.

현재 파서는 엄격한 문법 검증기가 아니다. 알 수 없는 단계 문장이 클릭으로 해석되거나, 단계가 없는 원문도 시나리오로 인식될 수 있다. 따라서 미리보기 생성 자체를 실행 가능 판정으로 취급하지 않는다.

#### 3.2 화면에서 단계 추출

1. ‘화면에서 추출’로 전환하고 편집할 시나리오를 선택한다.
2. URL을 입력하거나 내장 웹 화면에서 이동하여 대상을 확인한다.
3. ‘마커 추가’를 누르고 웹 화면에서 대상 위치를 선택한다.
4. 액션 정의 창에서 대상 라벨, 액션, 입력값, 조건, 안내 등을 확인·수정한다.
5. ‘마커 편집 완료’로 단계를 반영한다. 필요한 순서로 정렬한 뒤 저장하거나 바로 실행한다.

| ID | 항목 | 현재 동작 |
| --- | --- | --- |
| ED-07 | 화면 폭 | 모바일 390px, 태블릿 834px, 데스크톱 영역 전체 폭을 제공한다. 실행 화면의 viewport 설정과는 별개다. |
| ED-08 | 대상 추출 | 선택한 위치의 요소에서 라벨·텍스트·속성 등을 추출한다. select 요소는 선택 액션, 그 외에는 기본 클릭 액션으로 시작한다. |
| ED-09 | 단계 정보 | 대상 라벨, 액션, 조건, 입력·선택값, 업로드 파일 경로, 수동 안내 등을 액션에 맞게 편집한다. |
| ED-10 | 입력 검증 | 대상 라벨이 공백이면 완료할 수 없다. URL 형식이나 파일 존재 여부까지 사전 검증하지는 않는다. |
| ED-11 | 순서·삭제 | 드래그로 순서를 변경하고 개별 삭제, 마지막 삭제, 전체 초기화를 제공한다. 변경 후 단계 번호를 다시 부여한다. |
| ED-12 | 마커 표시 | 마커 보이기·숨기기를 제공한다. 좌표는 화면상의 표시·편집 정보이며, 실행은 액션별 대상 탐색으로 처리한다. |
| ED-13 | 대상 연결 확인 | 마커 모드 진입 시 별도 브라우저에서 기본 URL의 대상을 확인한다. 편집 웹 화면의 로그인 상태나 이전 조작을 재현하지 않으므로 연결 표시는 성공 보장이 아니다. |
| ED-14 | 편집 시나리오 전환 | 현재 마커 편집을 원문에 반영한 뒤 선택한 시나리오로 전환한다. 이 반영만으로 파일에 저장되지는 않는다. |

#### 3.3 지원 액션

| 액션 | 작성 예시의 단계 본문 | 동작 및 완료 기준 |
| --- | --- | --- |
| 페이지 이동 | `` `/orders` 페이지로 이동한다 `` | 기본 URL을 기준으로 해당 경로에 접속한다. |
| 자동 입력 | `` `이메일`에 `qa@example.com` 입력 `` | 입력 대상을 찾아 값을 입력한다. |
| 파일 업로드 | `` `첨부파일`에 `/path/sample.pdf` 파일 업로드 `` | 로컬 파일을 지정한 입력 요소에 설정한다. 경로가 없으면 실패한다. |
| 클릭 | `` `저장` 클릭 [대기 10초] `` | 대상을 찾아 클릭한다. 동일 대상은 `` `삭제` [2번째] 클릭 ``처럼 순번을 지정할 수 있다. |
| 값 선택 | `` `상태`에서 `완료` 선택 `` | 기본 select는 라벨 또는 값으로 선택하고, 커스텀 선택 UI는 대상과 옵션 클릭을 시도한다. |
| 텍스트 확인 | `` `저장 완료` 텍스트가 보인다 [대기 10초] `` | 제한 시간 안에 해당 텍스트가 보이면 통과한다. |
| 수동 입력 | `` `인증번호` 수동 입력 [인증번호를 입력해 주세요] `` | 사용자 입력을 기다린 뒤 대상 입력창에 전달한다. |
| 브라우저 직접 제어 | `` `인증` 브라우저 직접 제어 [인증을 완료해 주세요] `` | 실행 화면에서 사용자 조작을 전달하고 계속 또는 실패 응답을 기다린다. |
| 수동 결과 확인 | `` `결제 결과` 수동 결과 확인 [결과를 확인해 주세요] `` | 사용자가 성공 또는 실패를 판정한다. |

조건은 단계 앞에 `` 화면에 `텍스트`가 있는 경우 ``를 붙인다. 조건 텍스트가 보이지 않으면 해당 단계를 건너뛰며 실패로 계산하지 않는다. 조건 확인은 기본 최대 1초이며, 해당 단계에 보존된 대기값이 있으면 그 값을 사용한다.

클릭과 텍스트 확인의 기본 대기는 10초다. `[대기 N초]`는 모든 액션의 공통 정지 시간이 아니다. 자동 입력은 입력 후 대기, 클릭·텍스트 확인은 대상 확인 제한 시간으로 사용한다. 편집 UI에서 대기 시간을 직접 설정하는 액션은 클릭·텍스트 확인이며, 자동 입력·선택의 원문 대기값은 마커 저장·복제 시 유실될 수 있다.

#### 3.4 케이스 복제

미리보기의 복제 기능으로 원본의 흐름을 유지하면서 입력값·확인값이 다른 시나리오를 만든다.

| ID | 항목 | 현재 동작 |
| --- | --- | --- |
| ED-15 | 복제 단위 | 케이스를 1개 이상 입력하고 케이스마다 새 시나리오를 만든다. 케이스 추가·삭제를 제공한다. |
| ED-16 | 변경 가능 값 | 자동 입력·선택·파일 업로드 등의 입력값, 텍스트 확인·수동 결과 확인의 대상값을 바꾼다. URL·태그·단계 순서는 유지한다. |
| ED-17 | 제목 | 미입력 시 ‘원본 제목 복제’를 사용한다. 중복 이름에는 2, 3 등의 번호를 붙인다. |
| ED-18 | 빈 값 | 공백을 제거한 값이 비어 있으면 원본 값을 유지한다. 원본 값을 빈 문자열로 바꾸는 복제는 지원하지 않는다. |
| ED-19 | 반영·취소 | 복제 결과는 원문 끝에 추가된다. 파일 저장은 별도다. 취소하면 추가하지 않는다. |

수동 입력의 값 변경 UI는 존재하지만 원문 변환 시 해당 값이 저장되지 않는다. 따라서 수동 입력값을 미리 채우는 복제 기능으로 안내하지 않는다. 마커 좌표도 복제 원문에 포함하지 않는다.

### 4. 저장 및 이탈 정책

| ID | 상황 | 현재 동작 |
| --- | --- | --- |
| SV-01 | 텍스트 파일 저장 | 최초에는 저장 위치를 선택한다. 이후에는 현재 연결된 파일에 덮어쓰고 앱 기본 원문도 갱신한다. |
| SV-02 | 저장창 취소 | 저장 완료 처리와 저장본 갱신을 하지 않는다. |
| SV-03 | 마커 모드에서 편집기로 복귀 | ‘저장 후 돌아가기’, ‘저장하지 않고 돌아가기’, ‘취소’를 제공한다. |
| SV-04 | 저장 후 돌아가기 | 마커 내용을 원문에 반영하고 앱 기본 원문을 저장한다. 연결된 외부 파일이 있으면 함께 저장한다. 외부 파일이 없으면 별도 파일 저장창은 열지 않는다. |
| SV-05 | 저장하지 않고 돌아가기 | 텍스트 모드로 전환한다. 마커 상태·좌표를 이전 상태로 되돌리는 처리는 없으므로 ‘변경 완전 폐기’로 간주하지 않는다. |
| SV-06 | 복귀 취소 | 마커 편집 화면에 남는다. |
| SV-07 | 저장 실패 | 실패 메시지를 표시한다. 마커 저장 후 복귀는 실패하더라도 텍스트 모드로 이동한다. 두 저장소 중 일부만 저장될 수 있다. |
| SV-08 | 좌표 보존 | 마커 좌표는 원문과 별도로 자동 저장된다. 제목·URL 및 단계 정보가 달라지면 좌표 복원이 일치하지 않을 수 있다. |
| SV-09 | 앱 재시작 | 기본 원문과 좌표를 불러온다. 외부 파일과의 연결 경로는 재시작 후 편집기에 복원되지 않는다. |

마커 편집이나 복제 시 원문을 표준 문법으로 다시 생성하므로 기존 주석·서식·단계 접두사는 그대로 보존되지 않는다. 또한 일반 화면 이동이나 앱 종료 전의 공통 미저장 확인은 현재 확인되지 않는다.

### 5. 실행 대상 선택

| SL-06 | 실행 순서 | 파일 목록 순서, 각 파일 내부 시나리오 순서를 따른다. 사용자가 선택한 클릭 순서와는 다르다. |

‘선택자 미연결’은 원문 해석 결과에 따른 표시도 포함한다. 실제 대상 검사 결과나 실행 불가 판정으로 사용하지 않는다. 여러 파일에서 같은 내부 시나리오 ID가 생성될 수 있으며, 결과·캡처 매칭의 충돌 가능성은 별도 보완이 필요하다.

### 6. 실행 및 진행 확인

#### 6.1 실행 시작과 순서

| ID | 항목 | 현재 동작 |
| --- | --- | --- |
| RN-01 | 시작 조건 | 실행 배열이 비어 있으면 안내창을 표시하고 시작하지 않는다. URL 형식·최소 단계 수의 공통 사전 검증은 없다. |
| RN-02 | 실행 환경 | 화면에 별도 창을 띄우지 않는 Chromium으로 시나리오를 하나씩 순차 실행한다. |
| RN-03 | 시작 초기화 | 새 묶음 실행 시 진행률·로그·캡처·영상 경로·현재 결과를 초기화한다. 기존 최근 기록 전체를 삭제하지는 않는다. |
| RN-04 | 단계 순서 | 시나리오 기본 URL에 접속한 뒤 작성된 단계 순서대로 처리한다. |
| RN-05 | 실패 처리 | 한 단계가 실패하면 해당 시나리오의 남은 단계를 중단하고 다음 시나리오를 실행한다. 전체 시나리오 자동 재시도는 없다. |
| RN-06 | 화면 이동 | 다른 화면으로 이동해도 실행을 계속한다. 진행·완료 알림에서 실행 화면으로 돌아갈 수 있다. |
| RN-07 | 실행 중단 | 중단 버튼 한 번으로 취소를 요청하고 UI를 즉시 중단 상태로 바꾼다. 브라우저 종료와 남은 실행 중단을 요청한다. |

편집기의 ‘바로 실행’은 현재 마커 변경까지 반영한 전체 원문을 사용한다. 공통 하단 실행 버튼은 실행 화면에서는 기존 실행 목록을, 그 밖에서는 편집 원문에서 해석한 시나리오를 사용한다. 따라서 마커 편집 중 최신 변경을 실행할 때는 편집기 ‘바로 실행’의 반영 규칙과 구분한다.

#### 6.2 진행 화면

- 현재 시나리오·단계, 단계 진행률, 시나리오별 결과 및 소요 시간을 표시한다. 소요 시간은 시나리오마다 다시 측정한다.
- 완료되거나 조건 미충족으로 건너뛴 단계도 진행률에 반영한다.
- 실행 화면 표시, 실시간 미리보기, 단계 선택 시 해당 캡처 보기, 화면 크기·맞춤·확대 표시를 제공한다. 설정 메뉴의 화면 표시 체크박스는 실행 중 비활성화되지만, 화면 영역의 숨기기·표시 버튼은 별도로 동작한다. 현재 실행 묶음의 캡처 옵션은 시작 당시 값을 사용하므로 화면 표시 변경과 실제 캡처 중단은 동일하지 않다.
- 로그는 전체 또는 오류 필터로 볼 수 있다. 현재 오류 필터는 ‘실패’ 문구가 포함된 로그를 골라 표시한다.
- 단계 캡처 실패는 실행 자체를 중단하지 않는다. 이미지가 없거나 이전 이미지가 보일 수 있다.

브라우저 선택의 WebKit·Firefox와 worker 2·4는 버튼 표시만 있으며 실제 전환 동작이 없다. ‘창 분리’도 현재는 알림·로그만 제공하고 새 창을 만들지 않는다. 이 항목들은 지원 완료 기능에 포함하지 않는다.

#### 6.3 실행 중 수동 개입

| 구분 | 사용자 동작 | 대기·결과 정책 |
| --- | --- | --- |
| 수동 입력 | 실행 화면에서 값을 입력하고 ‘입력 완료 · 계속’ | 기본적으로 입력값을 가리고 표시 토글을 제공한다. 응답 제한 시간은 없다. 취소는 단계 건너뛰기가 아니라 실행 취소다. 빈 값 제출을 차단하지 않는다. |
| 브라우저 직접 제어 | 실행 화면에서 클릭·키보드·스크롤·붙여넣기 등으로 조작한 뒤 계속 또는 실패 | 같은 실행 브라우저에 조작을 전달한다. 최대 5분이며 초과 시 실패한다. 실패 제출에는 사유가 필요하다. |
| 수동 결과 확인 | 확인 모달에서 성공 또는 실패 선택 | 최대 5분이며 초과 시 실패한다. 실패 제출에는 사유가 필요하다. |

수동 입력·직접 제어는 실행 화면으로 돌아와 응답한다. 수동 결과 확인은 전역 모달로 노출된다. 시간 초과·취소 이후 이전 수동 UI를 일괄 정리하는 처리가 완전하지 않아 상태 정합성 확인이 필요하다.

#### 6.4 세션 유지

한 실행 묶음 내 시나리오는 브라우저 컨텍스트를 공유하며, 시나리오마다 새 페이지를 연다. 쿠키 등 공유 상태가 다음 시나리오에 영향을 줄 수 있으므로 각각이 완전히 독립된 테스트라고 가정하지 않는다.

| ID | 상황 | 현재 동작 |
| --- | --- | --- |
| SS-01 | 기본 설정 | 세션 유지 꺼짐. 묶음 종료 시 실행 브라우저를 정리한다. |
| SS-02 | 세션 유지 켬 | 실행이 끝나도 컨텍스트를 유지하여 다음 실행에서 재사용한다. 실행 도중 켜면 현재 사용 중인 컨텍스트를 유지 대상으로 삼는다. |
| SS-03 | 실행 중 끔 | 현재 실행은 계속하고 종료 시 정리한다. |
| SS-04 | 대기 중 끔·세션 종료 | 유지 중인 세션을 종료한다. 별도 ‘세션 종료’ 버튼은 실행 중 비활성화된다. |
| SS-05 | 실행 중단 | 유지 중이던 세션도 종료된다. 다음 실행에 인증이 다시 필요할 수 있다. |
| SS-06 | 앱 종료 | 정상 앱 종료 시 실행 컨텍스트를 정리한다. 세션을 디스크에 저장해 다음 앱 실행에서 복원하는 기능은 아니다. |

세션 유지는 인증 정보를 재사용하는 기능이다. 로그인 단계 자체를 자동 삭제하거나 건너뛰는 기능은 없으며, 대상 서비스의 인증 만료도 자동 복구하지 않는다.

### 7. 결과 확인과 재실행

#### 7.1 판정 및 보존

| ID | 항목 | 현재 동작 |
| --- | --- | --- |
| RS-01 | 시나리오 통과 | 오류 없이 모든 단계를 처리하면 통과한다. 전부 조건 미충족으로 건너뛴 경우나 단계 없이 URL 접속만 성공한 경우도 통과할 수 있다. |
| RS-02 | 시나리오 실패 | 액션 오류, 기대 텍스트 미확인, 수동 실패 판정, 수동 제어·판정 시간 초과 등으로 실패한다. |
| RS-03 | 묶음 판정 | 일반 완료 시 실패 시나리오가 하나라도 있으면 묶음을 실패로 기록한다. 요약의 실행 횟수는 시나리오 수가 아닌 묶음 수다. |
| RS-04 | 최근 실행 기록 | 최대 5개 묶음을 메모리에 보관한다. 앱 재시작 후 기록과 요약을 복원하지 않는다. |
| RS-05 | 결과 리포트 | 시나리오 결과·로그를 로컬 HTML 및 JSON으로 저장한다. 현재 기록 UI는 이 파일을 재시작 시 불러오는 구조가 아니다. |
| RS-06 | 캡처 | 단계별 최신 캡처를 메모리에 보관한다. 영구 스크린샷 이력은 아니다. |
| RS-07 | 영상 | 단일 시나리오 영상을 저장하고 일반 묶음 완료 후 전체 영상 병합을 시도한다. 다운로드는 OS 다운로드 폴더로 복사한다. |
| RS-08 | 영상 오류 | 병합·영상 처리 오류는 테스트 판정을 변경하지 않는다. 영상이 누락될 수 있다. |
| RS-09 | 보존 기간 | 리포트·실행 영상의 기간별 자동 삭제 정책은 구현되어 있지 않다. UI 기록 5개 제한은 파일 보존 개수 제한이 아니다. |

실행 중 취소가 반영되면 일반적으로 묶음 기록과 전체 영상 병합을 생략하지만, 이미 생성된 단일 리포트·영상은 삭제하지 않는다. 병합이 이미 시작된 시점에는 중단 요청으로 작업을 되돌리지 못한다. 취소 시 UI 상태와 파일에 기록된 실패·취소 상태가 다를 수 있다.

#### 7.2 재실행과 대기열

| ID | 항목 | 현재 동작 |
| --- | --- | --- |
| RR-01 | 기록 재실행 | 해당 기록에 저장된 시나리오 묶음을 실행한다. 현재 편집 원문을 다시 읽지 않는다. |
| RR-02 | 개별 재실행 | 실행 화면에서 완료된 시나리오를 다시 실행한다. 다른 시나리오의 화면 결과는 유지하고 해당 결과를 갱신한다. |
| RR-03 | 대기열 추가 | 실행 중이거나 대기열이 멈춰 있으면 재실행을 대기열에 넣는다. 실행이 없고 대기열도 없으면 즉시 실행한다. |
| RR-04 | 처리 순서 | 먼저 추가한 항목부터 실행한다. 실패로 끝나도 취소가 아니면 다음 대기 항목으로 진행한다. |
| RR-05 | 일시정지·재개 | 일시정지는 다음 항목의 자동 시작을 멈춘다. 현재 실행을 정지하는 기능은 아니다. 재개하면 실행 중이 아닐 때 다음 항목을 시작한다. |
| RR-06 | 제거·비우기 | 대기 항목 개별 제거와 전체 비우기를 제공한다. 현재 실행 중인 항목을 취소하는 기능은 아니다. |
| RR-07 | 실행 중단과의 관계 | 중단해도 대기열을 비우지 않는다. 자동 다음 실행은 진행하지 않으며 재개 조작이 필요하다. |
| RR-08 | 기록 반영 범위 | 개별 재실행은 현재 결과를 갱신하지만 묶음 기록·요약을 새로 생성하거나 전체 영상을 다시 병합하지 않는다. |

같은 시나리오가 대기열에 있으면 화면의 재실행 버튼 대신 ‘대기열에 있음’을 표시한다. 다만 대기열 추가 함수 자체에 중복 차단이 없어 데이터 차원의 유일성까지 보장하지는 않는다.

| 실행 전 유효성 | URL·최소 단계 수·문법을 엄격히 검증하지 않음 | 필수값과 실행 차단 오류를 정의하고 오류 위치를 안내 |
| 미저장 변경 폐기 | 저장하지 않고 돌아가도 마커·좌표를 원복하지 않음 | 저장·임시 반영·폐기의 의미를 통일하고 화면 이탈 정책 결정 |
| 저장 일관성 | 기본 원문·외부 파일·좌표가 각각 저장됨 | 부분 저장 실패 시 표시와 복구 기준 결정 |
| 실행 중복·중단 상태 | 공통 시작 함수에 실행 중 재호출 차단이 없고 늦은 이벤트·응답이 남을 수 있음 | 동시 시작 차단, 취소 완료 시점, 이전 이벤트 폐기 기준 정의 |
| 수동 단계 만료 | 입력은 무제한, 직접 제어·판정은 5분이며 잔여 UI가 남을 수 있음 | 대기 시간·만료 안내·화면 이탈 후 복귀 규칙 통일 |
| 여러 파일의 결과 식별 | 파일별 시나리오 ID가 중복될 수 있음 | 파일을 포함한 고유 식별 기준으로 결과·캡처 연결 |
| 성공의 의미 | 단계가 없거나 전부 건너뛰어도 통과 가능 | 실행 없음·전체 건너뜀의 별도 결과 필요 여부 결정 |
| 실행 기록 일관성 | 개별 재실행 결과와 과거 묶음 기록이 다를 수 있음 | 새 기록 생성 또는 기존 기록 갱신 중 제품 정책 결정 |
| 세션 격리 | 묶음 내 상태 공유, 선택적으로 묶음 간에도 유지 | 독립 검증과 연속 업무 흐름의 세션 기준 결정 |
| 데이터·산출물 보존 | 영상·리포트 자동 삭제와 영상 마스킹 없음 | 보관 기간·삭제 방식·민감정보 노출 범위 결정 |
| 문법 보존 | 마커 편집·복제에서 서식과 일부 값이 유실될 수 있음 | 지원 문법과 왕복 변환 보장 범위 확정 |

대상 사이트에서 이미 수행된 저장·제출·업로드는 실패나 취소로 되돌리지 않는다. 테스트 데이터 정리나 업무 변경의 롤백은 현재 실행 기능에 포함되지 않는다.

### 9. 인수 확인 항목

다음은 이 기획서의 동작을 검증하기 위한 체크리스트다. 이번 문서 작성에서 실측 완료한 결과는 아니다.

- [ ] 표준 원문 작성 시 시나리오·단계·액션이 미리보기와 일치한다.
- [ ] 마커 추가·수정·삭제·정렬 후 바로 실행에 최신 편집 내용이 반영된다.
- [ ] 복제 케이스별 값 변경, 제목 중복 번호, 빈 값의 원본 유지가 일치한다.
- [ ] 파일 불러오기·저장·취소·실패·앱 재시작에 따른 원문 및 좌표 상태를 확인한다.
- [ ] 여러 파일 선택 시 파일 목록과 파일 내부 순서대로 실행한다.
- [ ] 자동 액션 성공·실패, 조건 미충족, 클릭 순번, 텍스트 확인 제한 시간을 확인한다.
- [ ] 한 시나리오 실패 후 다음 시나리오가 실행된다.
- [ ] 수동 입력 취소와 직접 제어·수동 판정의 성공·실패·시간 초과를 확인한다.
- [ ] 화면 이동 중 실행이 계속되며 복귀 후 진행과 결과를 확인할 수 있다.
- [ ] 세션 유지 켜기·끄기·종료·실행 중단에서 쿠키 등 공유 상태를 확인한다.
- [ ] 개별 재실행과 대기열 일시정지·재개·제거·비우기가 정의한 범위로 동작한다.
- [ ] 중단 직후 새 실행, 병합 중 중단에서 늦은 이벤트·결과 혼입 여부를 확인한다.
- [ ] 단일·전체 영상 다운로드와 영상 오류 시 테스트 판정 유지 여부를 확인한다.
- [ ] 최근 기록 5개 제한과 앱 재시작 후 UI 기록·로컬 파일의 보존 차이를 확인한다.
